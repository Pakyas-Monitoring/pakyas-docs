Create `src/content/docs/cli/api-key.md` following the pattern in monitor.md.

Include the following sections based on RESEARCH.md:

1. **Frontmatter:**
   - title: api-key Command
   - description: Create and manage API keys on the server

2. **Intro paragraph:** Explain this command manages API keys on the Pakyas server (not local credentials). Contrast with `auth key` which manages locally stored keys.

3. **Differentiation callout:**
   - auth key = local credential storage (which keys to use)
   - api-key = server-side key management (create/revoke keys)

4. **api-key list section:**
   - Usage: `pakyas api-key list`
   - Shows: name, ID, prefix, scopes, created date, last used, status
   - Requires active organization

5. **api-key create section:**
   - Usage: `pakyas api-key create <NAME> [-s SCOPES] [--expires DAYS]`
   - NAME is required positional argument
   - Flags:
     - -s/--scopes: read, write, manage (comma-separated, defaults to read)
     - --expires: 1-365 days (omit for no expiration)
   - Important: Full key shown ONCE, cannot be retrieved later
   - Examples:
     - Create read-only key for monitoring
     - Create CI/CD key with write scope and 90-day expiry
     - Create admin key with manage scope

6. **api-key revoke section:**
   - Usage: `pakyas api-key revoke <ID> [-y]`
   - ID from list output
   - Flags: -y/--yes (skip confirmation)
   - Warning: Cannot be undone

7. **Scope Reference table:**
   - read: Read-only access (list checks, view status)
   - write: Read + write (create/update checks, send pings)
   - manage: Full access (includes key management)

8. **Common Workflows section:**
   - Creating keys for CI/CD pipelines
   - Rotating keys (create new, update CI, revoke old)
   - Scoped keys for different environments

9. **See Also:**
   - Link to auth command (local credential management)
