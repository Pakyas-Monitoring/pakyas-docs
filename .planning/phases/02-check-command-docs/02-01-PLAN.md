2. Introduction paragraph explaining tail shows recent and real-time events

3. Sections:
   - ## Usage
     ```bash
     pakyas check tail <SLUG> [FLAGS]
     ```

   - ## Arguments table with SLUG (required)

   - ## Flags table:
     | Flag | Description |
     |------|-------------|
     | `--since <TIME>` | Show events since time (default: 30m). Accepts durations (30m, 1h, 2d) or ISO timestamps |
     | `--types <TYPES>` | Filter by event types: signal, state, alert (comma-separated) |
     | `-f, --follow` | Follow mode - continuously poll for new events |
     | `--limit <N>` | Events per request (default: 50) |
     | `--format <FORMAT>` | Output format: human (default), json, ndjson |

   - ## Event Types section:
     | Type | Events | Description |
     |------|--------|-------------|
     | signal | run_started, run_finished | Ping events from your jobs |
     | state | status_changed | Check status transitions |
     | alert | alert_decision | Alert notifications |

   - ## Duration Format section showing accepted formats:
     - Duration strings: 30m, 1h, 2d, 1w
     - ISO timestamps: 2024-01-01T00:00:00Z

   - ## Examples with practical use cases:
     - Default last 30 minutes
     - Custom time range with duration
     - Custom time range with timestamp
     - Follow mode for real-time monitoring
     - Filtering by event type
     - Combined options
     - NDJSON output for streaming to other tools

   - ## See Also linking to check-inspect, check-doctor

Use :::tip for recommending --follow with --format ndjson for pipelines.
